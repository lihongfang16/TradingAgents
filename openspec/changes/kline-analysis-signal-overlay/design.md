## Context

当前实现中，自选股监控面板的K线图 (`render_candlestick_chart`) 仅渲染原始价格数据（OHLCV），AI分析信号以文本形式单独显示在图表下方。这种分离的展示方式导致：
1. 用户无法直观看到信号产生时的具体价格位置
2. 无法追踪连续交易信号形成的交易轨迹
3. 缺乏信号置信度与价格走势的关联性展示

需要引入分析历史数据API和增强的K线图渲染，实现信号与K线的叠加显示。

## Goals / Non-Goals

**Goals:**
- 提供后端API查询自选股分析历史时间序列
- 在K线图上用箭头标记每个分析信号（BUY/SELL/HOLD）
- 实现买卖信号连线，可视化交易轨迹
- 区分盈利/亏损交易连线样式
- 添加完善的错误状态提示

**Non-Goals:**
- 不修改分析引擎核心逻辑
- 不引入新的数据源
- 不实现实时推送（SSE），采用轮询刷新
- 不支持除A股以外的市场

## Decisions

### 1. 使用 Plotly add_annotation + add_shape 实现信号标记和连线
**选择**：使用 Plotly 的 `add_annotation()` 添加箭头标记，`add_shape()` 添加连接线。
**理由**：Plotly 已用于K线图渲染，无需引入新依赖；annotations支持丰富的样式定制；shapes支持虚线/实线切换。
**替代方案**：使用 `add_trace()` 添加散点标记—— rejected，因为 annotations 更灵活，可独立控制箭头样式。

### 2. 分析历史存储在 WatchlistAnalysis 表
**选择**：复用现有的 `WatchlistAnalysis` 模型存储分析历史。
**理由**：该表已设计用于存储自选股的分析结果，包含 signal、confidence、price、created_at 字段，满足需求。

### 3. 按分析时间戳匹配K线数据点
**选择**：将分析历史的时间戳映射到K线数据的最近数据点。
**理由**：1分钟K线数据有明确的时间索引，可通过最近邻匹配找到对应价格位置。
**权衡**：如果分析发生在非交易时间（如收盘后），会匹配到最近的交易时间点，可能产生轻微位置偏差。

### 4. 盈利/亏损判定逻辑
**选择**：BUY信号后的SELL信号，如果卖出价 > 买入价则为盈利；SELL信号后的BUY信号，如果买入价 < 卖出价则为盈利。
**理由**：简单的配对逻辑，直观反映交易结果。
**注意**：此逻辑不考虑持仓时间成本，仅作为可视化辅助。

## Risks / Trade-offs

- **分析历史数据量大** → 限制API返回最近50条记录，前端按需加载
- **K线图渲染性能下降** → 信号标记使用简单shape，避免复杂SVG
- **时间戳匹配不准确** → 添加容错处理，匹配最近的有效K线点
- **API向后兼容性** → 新端点使用版本控制（v1），不影响现有接口
